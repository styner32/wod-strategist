# Workout context sharing

- `GET /api/v1/sessions/:session_id/share-context` uses existing app authentication. `profile_id` is required; `timezone` is an IANA zone, default `Asia/Seoul`. The response is `Cache-Control: no-store`. No external credential, public URL, LLM request, or database migration is created by this feature.
- The owned analysis must be `COMPLETED`, nonarchived and `analysis_type=wod`. This includes all workout types (`wod`, `warmup`, `accessory`, `cooldown`), and owned legacy analyses without a `sessions` row. Injury-supplement analyses cannot be exported.
- Assemble the data in a read-only repeatable-read transaction. Schema version is `1`; arrays are always nonnull. The envelope has `generated_at`, `timezone`, `session`, `confirmed_records`, `comparisons`, `baseline_records`, `observations`, `unassessed`, `sensor_summary`, `effort`, and `warnings`.
- Workout time comes from canonical `workout_at` with `session_ulid` or `legacy_local_time`. Created-at fallbacks remain `performed_at:null`. Unknown workout time never becomes the export or confirmation time, and suppresses chronological comparisons.
- Current confirmations require the current observation `source_version` and pass `workoutprogress.ActiveRecords`. Incomplete/rest records and null counts remain distinguishable. Never fill unknown counts, loads or sensor values with zero.
- Prior comparisons use the same owned profile, a different strictly earlier session, completed/nonarchived current-source analysis, and a record time/source matching canonical analysis time/source. Restrict candidate sessions by movement, but retain all their confirmations until session-local supersession has run, so a later rest or different-movement confirmation can supersede an old record.
- Use `workoutprogress.ComparisonFor` only for selected current records. Do not call bulk `Comparisons(history+current)` per current record: it recomputes historical comparisons quadratically. Preserve deterministic query ordering and every referenced direct/reference/lower-load baseline. Reference comparisons have condition differences and no pace-change percentage.
- AI interval summaries are independent, including intervals with user confirmations. They export observed complete-rep counts and form/ROM/pace evidence, not raw rep events. They must not be added to confirmed counts. Unassessed ranges are not rest; interval timestamps refer to media positions and elapsed time is separate.
- Sensor output is a small allowlisted projection of `populateHeartRateSummary`, including its freshness/quality validation. It contains measured average/peak BPM, coverage, valid/excluded/unknown seconds and calculation version. Pending/failed/stale results have status without retained successful metrics. No device identity, raw telemetry, profile attributes, videos, signed URLs or storage paths are exported.
- `shared/workoutShare.ts` owns the cross-platform DTO and `buildWorkoutShareText(context, options, locale)`. It reads the same KO/EN JSON resources as the mobile app without importing Expo into the web bundle. It formats explicit fields rather than serializing arbitrary objects. Both `includeAIObservations` and `includeSensorSummary` default to true in the preview; the latter also controls user-reported effort. Evidence limitations remain visible when AI observations are excluded.
- Web entry: active completed session details → “AI에 물어보기” → exact selectable preview, clipboard or UTF-8 `.txt`. Mobile entry: active completed history card → same preview/options → `Share.share`, with manual text selection fallback. Fetch only on open, cancel/ignore stale requests on close/scope changes, reset on reopen, and keep snapshot/options after a share error or system-share dismissal. Android share completion does not prove receipt by another app.
- Snapshot sharing does not grant live access or support revocation after copying; later edits are not reflected in already-exported text. Account-linked MCP and response import remain outside v1.

Validation: focused share-context controller specs use a migrated temporary PostgreSQL database; comparison tests use the existing Ginkgo suite; shared formatter and web/mobile interaction tests use Jest. Native share target acceptance still requires an actual iOS/Android device.
