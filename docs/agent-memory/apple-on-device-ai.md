# Apple on-device AI feedback experiment

- `onDeviceAi` is a persisted setup boolean and a `"true"`/`"false"` recording route param, default OFF on every platform. Preview does not analyze. Do not repurpose `showSkeleton`: the existing MoveNet detector/overlay remains independent.
- Local Expo module: `modules/apple-on-device-ai`, Swift module `apple_on_device_ai`, Expo name `AppleOnDeviceAi`. Run `pod install` and rebuild iOS after adding/updating it; a JS-only refresh cannot install a native module. Optional import keeps Android, older binaries and Expo Go usable.
- App minimum stays iOS 16.4. Foundation Models is weak-linked; image inference is guarded by iOS 27, `SystemLanguageModel.default.availability`, `.capabilities.contains(.vision)`, and `supportsLocale`. Never gate solely on a device name or silently use a cloud provider.
- Inputs: 6 candidate camera snapshots with 800ms waits (about 4 seconds plus capture overhead), `wodDescription`, `movements`, `appearanceHints`, current app language. Native `prepareFrames(requestId, frames)` selects 3 chronological JPEG inputs and applies a common person/context crop. See the preprocessing contract below. Times are snapshot acquisition times, not verified video presentation timestamps. This samples images, not an entire video.
- A fresh explicit on-device session generates 1–3 feedback sentences, at most 256 output tokens. WOD is context, not proof of the current movement; images/context are data, not instructions. No MoveNet/Gemini judgments, previous answers, rep counts, depth/angle scores, or safety guarantees are fed in or inferred by app-side code.
- Normal schedule: collect → prepare → analyze → archive evidence locally → clean temporary files → wait 10 seconds. One request at a time. Native deadline is 30 seconds. Cancellation retains the native slot until inference settles; JS also waits for the old run to settle before resuming. Late responses are discarded. Native actor remembers early cancellation IDs to handle bridge ordering.
- Pause, stop, screen blur, background, option OFF, or changed session/context cancels the loop. Stop/pause handlers abort before waiting for the last video chunk. Snapshot files returned after cancellation must still be archived and then deleted; never delete a file while native analysis could still be reading it or before successful archive persistence.
- While enabled and foregrounded, poll `expo-battery` and native thermal state every 5 seconds. Battery <=15%, OS low power, or thermal serious/critical stops Apple analysis only. Native thermal notifications also cancel active inference. Recovery requires >=20% for a low-battery latch, OS low power off, thermal below serious, then 30 seconds without a blocking condition. Unknown readings do not clear established protection. Existing video/MoveNet/Gemini are unchanged.
- The UI distinguishes availability, collection, inference, previous-result waiting, protection and failures. Keep capture times unchanged while waiting. Feedback text is shown verbatim; model refusals/errors are not posture findings. `OPT FLAGS` includes `apple-ai:<status>`.
- `onDeviceAi` also enables evidence archiving/upload; the setup description in both locales discloses this. Input snapshots and feedback are retained for review, including failed/partial/cancelled attempts. Standard video upload remains unchanged; do not call `/chunk-complete`, `/upload-complete` or sensor processing endpoints for these files.

## Evidence storage and upload

- `appleAiObservation.ts` defines a per-request observation. `useAppleAiFeedback` awaits `onObservation` in `finally`, after native inference settles and before deleting temporary snapshots. `stop()` aborts immediately and returns the in-flight completion promise. Recording stop/pause/unmount flush only after that promise settles, so the last result is included. Old requests keep their original session/profile/start time even if a new recording starts.
- `appleAiUpload.ts` copies original input JPEGs into `Documents/apple-ai/{ULID}/`, writes `manifest.tmp`, then renames to `manifest.json`. A committed manifest is the durable upload queue entry; no shared mutable queue index is needed. Save failures surface `archiveError` in the feedback card and preserve source snapshots. Incomplete writes/directories are not uploaded automatically; a crash/disk failure before commit may require local recovery. A process killed before the result is archived cannot produce a recovered response.
- Upload uses existing authenticated `POST /upload-url` with the original `profile_id`, `session_id` and flat filenames. GCS objects are `videos/{pid}/{sid}/apple_ai_{ULID}_frame_{1..6}.jpg` (original candidates), `apple_ai_{ULID}_input_{1..3}.jpg` (prepared JPEG inputs), and `apple_ai_{ULID}.json`. Partial attempts can contain fewer candidates and no prepared images. Preserve originals for review. Expect extra disk/network usage, especially at 4K; model token savings do not imply upload savings.
- New JSON uses `schemaVersion: 2`, `promptVersion: 3`; uploader still accepts queued schema 1/2 and prompt 1/2 bundles. Includes model selector (`SystemLanguageModel.default`, not a claimed model build), context, outcome/error/answer, capture timestamps and offsets. `frames` are original candidates. Optional `preparation.frames` link exact encoded model inputs by zero-based `sourceIndex` into `frames`, filename/objectName, original capture time, and pixel dimensions. Preparation records normalized top-left crop, mode/reason, candidate/person counts, selection method, change scores, and preparation latency. Native temporary paths are never uploaded. `inferenceStartedAt` is present only if JS dispatched the model call; prepared images on a cancelled attempt do not prove inference ran. Cancelled/late/timed-out responses have `answer: null`, but preparation is retained. Bump prompt version when changing instructions.
- `captureOffsetMs = capturedAt - sessionStartedAt` includes pauses and is **not** a merged-video seek position. `clock` explicitly labels this limitation. Source paths and signed URLs are not stored in uploaded JSON; frame filenames/object paths link the evidence.
- Upload all JPEGs first, then JSON as the remote completion marker. On success rename the local manifest to `uploaded.json`, then delete the bundle. Startup cleans any already-uploaded remnants without needing their images again. Failed transfers retain the whole bundle and retry the same object names; do not drop after a fixed number of attempts. Discovery derives paths from current `documentDirectory`, allowing an iOS container path change.
- Flush is serialized and coalesces concurrent calls, including a new entry queued during upload. Triggers: recording stop/pause/unmount, authenticated app launch/login, and return to foreground. This is not an OS background scheduler; termination can defer work until the next trigger. Each attempt obtains fresh signed URLs. `uploadSessionAssetToGcs` preflights local files and uses legacy `uploadAsync`, shared with sensor uploads to avoid constructing a native task for a missing file.
- No new backend endpoint, migration or server deployment is required for AI evidence upload. The original upload-only addition needed no native rebuild; crop/selection now does require one. Files are for storage-level/manual inspection; history screens do not render Apple AI results yet. Previously displayed results were not archived and cannot be backfilled.


## Representative input preprocessing — 2026-09-21

- `AppleAiFramePreprocessor.swift` uses Apple Vision `VNDetectHumanRectanglesRequest` (`upperBodyOnly = false`), not MoveNet or a posture classifier. Images are processed sequentially at maximum 768px with EXIF orientation applied. No full-resolution image buffers cross JS. Native preparation shares the actor's request slot, cancellation and thermal suppression; JS stop waits for preparation, archival and cleanup before restarting.
- `AppleAiFrameSelection.swift` requires exactly one confidence >=0.5 human detection in every candidate, usable bounds, and >=20% overlap relative to the smaller neighboring person box. Missing/multiple/tiny/edge-touching/jumping detections, Vision failure or changed image dimensions keep the full frame. This does not certify identity or complete visibility.
- Use the union of all detected person rectangles for a common crop. Margins are 65% of union width on each side, 40% of union height above and 25% below, clamped to image bounds. If >90% of the frame is needed, preserve the whole frame. This is a conservative **context heuristic, not equipment recognition**; long bars/ropes can still extend beyond it. Validate with real lifting/pull-up footage before tightening margins.
- For a reliable subject, compare 32×32 grayscale descriptors of its fixed union region. Mean-center brightness and use mean absolute differences. Keep first/last candidates; choose the interior candidate maximizing its minimum difference from those endpoints. Below 0.015 use chronological indices `[0, 2, 5]`. This detects visual change, not a movement phase or pose quality; camera motion/blur can affect it. On unreliable-subject fallback, use uniform indices and `selectionMethod: uniform_unreliable_subject`, with empty (unmeasured) `changeScores` instead of scoring background activity.
- Crop the already bounded 768px EXIF-corrected source, with outward integer pixel rounding; never upscale. JPEG quality is 0.9. The same saved JPEG is decoded for model inference and archived. Outputs can be smaller than 768px; no guaranteed token/latency/battery reduction is claimed. Normal archival now includes up to 9 JPEGs, so storage/network costs increase during this experiment.
- Selection mode is `endpoints_plus_visual_change`, `uniform_low_change`, or `uniform_unreliable_subject`. Crop mode is `person_with_context` or `full_frame`; `fallbackReason` identifies the reason. New native API is required: JS additionally requires native `promptVersion === 3`; older binaries report `module_missing` instead of silently dropping appearance context after a JS-only upgrade.
- Prompt 2 asks for a combined observation across selected samples, gives relative capture times, and explains that visual-change selection is not verified movement recognition. Existing anti-hallucination/occlusion/multiple-person rules remain in force. Test extraction quality separately from the prompt change to avoid attributing all response differences to cropping.
